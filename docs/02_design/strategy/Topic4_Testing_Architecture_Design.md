# 주제 4: 테스트 아키텍처 설계

이 문서는 시스템의 안정성을 보장하기 위한 다단계 테스트 전략을 정의합니다.

## 테스트 계층 구조

### 1. 단위 테스트 (Unit Tests)
- **대상**: `Parser`, `RAG`, `IRAdapter`, `LLMProvider` 등 개별 모듈.
- **방법**: 외부 의존성(LLM API 등)을 Mocking 하여 순수 로직만 검증.
- **폴더**: `tests/unit/`

### 2. 통합 테스트 (Integration Tests)
- **대상**: `CoreEngine`에서 어댑터 실행까지의 전체 파이프라인.
- **방법**: 실제 목업 데이터(`mock_tc_data.tsv`)를 입력으로 사용하여 최종 코드가 생성되는지 확인.
- **폴더**: `tests/integration/`

## 주요 검증 시나리오
- **RAG 정확도**: 특정 자연어 입력에 대해 예상된 논리 시그널이 검색되는지 확인.
- **Pydantic 복원력**: LLM이 잘못된 JSON을 반환했을 때 자기 수정 루프가 정상 작동하는지 확인.
- **어댑터 무결성**: 생성된 파이썬 코드가 구문 오류 없이 실행 가능한 형태인지 확인.

## 자동화 도구
- **Pytest**: 표준 테스트 프레임워크로 사용.
- **Coverage.py**: 테스트 커버리지를 측정하여 미흡한 영역 식별.
