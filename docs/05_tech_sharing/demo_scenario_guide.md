# 💻 기술 공유 시연 시나리오 가이드 (Live Demo Scenario)

기술 공유 중반부 혹은 결론 직전에 청중의 몰입도를 극대화하기 위한 **통합 라이브 데모(Live Demo)** 진행 가이드입니다.
이 데모는 프로젝트의 방대한 엔진 설정 없이도 즉각적으로 실행될 수 있도록 `demo/data` 폴더 내의 **간소화된 샘플 DB**를 활용하여 동작합니다.

---

## 🚀 데모 환경 준비 및 실행 방법

1.  **실행 환경**: 프로젝트 루트 디렉터리의 터미널 (Python 3.9+ 권장, 패키지 의존성 문제없음 확인)
2.  **실행 명령어**:
    ```bash
    python docs/05_tech_sharing/demo/demo_cli_app.py
    ```
3.  **데이터 구조 (미리 파악 권장)**: 
    *   샘플 시그널(`sample_vector_db.json`): 할당 동작(`action_set_signal`), 판정 동작(`check_signal_eq`) 등 시스템 상의 **범용 동작 액션 템플릿**들이 들어 있습니다.
    *   샘플 온톨로지(`sample_ontology.json`): `좌측 헤드램프`, `차량 속도` 등의 자연어 개념이 실제 ECU 제어 시그널(물리 노드)로 매핑되며, 조작 전 확인해야 할 **"전원 조건", "센서 이상 조건" 등 제약 조건 그래프**가 연결되어 있습니다.
    *   데모 RAG 엔진(`demo_rag_engine.py`): 코어 로직의 무결성을 지키면서 방안 C(Action 분리) 모델을 시연하기 위해, **데모 스크립트 전용으로 파싱 로직을 분리 독립**시킨 커스텀 모듈입니다.

---

## 💾 데모 시연 중 DB 핵심 확인 포인트

기술 공유 중 청중에게 RAG 시스템의 우수성을 돋보이게 하기 위해, 데모 시연 중에 로그를 통해 **다음의 DB 매칭 포인트**를 중점적으로 확인하고 강조해야 합니다. (DB의 기본 구조 자체는 설계 문서와 동일하게 동작함)

### 1. Vector DB 매칭 로그: "동작 의도(Action) 추출" 확인
데모 과정에서 단순한 단어 매칭이 아닌, 사용자가 입력한 자연어 문장의 **'행위 의도'**를 정확히 판별하는지 확인합니다.
*   **강조 포인트**: 로그 상에 나타나는 `[Vector DB Action Match]` 결과를 주목하십시오.
*   예를 들어, "켜라", "작동시켜라" 등의 문장이 `action_set_signal`이라는 공통 템플릿(골격)으로 매핑되는 과정을 통해 Vector DB가 단순 검색이 아닌 의도 판별기로 작동함을 어필합니다.

### 2. Ontology DB 탐색 로그: "제약조건(Constraint) 연계" 확인
Ontology 그래프 매핑 시, 단순한 단어 번역(Concept -> Physical Signal)을 넘어 시스템이 **숨겨진 도메인 지식**을 어떻게 끄집어오는지 확인합니다.
*   **강조 포인트**: 로그에 출력되는 `[Graph Hop - Constraint Discovered]` 메시지를 가리킵니다.
*   데모 시연 시 "좌측 전조등을 켜라"고 명령했을 때, 온톨로지 DB가 단순히 시그널 ID만 던져주는 것이 아니라 사전 조건인 "IG 전원 및 배터리 공급 상태 확인"이라는 제약 사항까지 자동으로 함께 도출(Prompt 주입)함을 시각적으로 증명합니다.

## 🎬 데모 진행 시나리오 (스토리텔링)

**[목표]**: 단순한 "유사도 검색(RAG)"을 넘어선 **Contextual RAG(문맥 + 온톨로지 연결)**의 작동 원리와 **실제 LLM 코드 조립 과정**, 그리고 **캐시(Cache)로 인한 즉각적인 속도 향상**을 한 편의 흐름으로 시연합니다.

### Step 1: 방안 C의 진수, "2-Step RAG 모델"의 시각적 증명
1.  **입력**: `"좌측 전조등을 켜라"` 입력
2.  **연출 (1단계 - Vector DB의 Action 추출)**:
    *   `[Vector DB 매칭 성공]` 로그와 함께 입력된 자연어가 `action_set_signal`이라는 '할당 동작'으로 추상화되는 과정을 강조합니다.
3.  **연출 (2단계 - Ontology 지식 그래프 탐색 및 Graph Hop)**:
    *   `[Ontology 매칭 성공]` 컨셉 노드 검색 및 실제 물리 시그널 매핑 과정을 보여줍니다.
    *   `[Graph Hop] 제약조건(Constraint) 노출` 파트를 지목하며, "이 시그널 조작 전 배터리 전원이 ON이어야 정상 작동합니다"라는 제약 사항이 자동으로 도출되는 점을 강조.

### Step 2: 3-Tier Extractor로 변수 추출 (결정론적 방어막 시연)
1.  **연출 (Tier-1, 2 Extractor 활성화 로그)**:
    *   입력 문장에 포함된 파라미터(값)를 DB 정규식을 기반으로 안전한 값(예: `ON`)으로 매핑하는 로그를 보여줌.

### Step 3: LLM의 조립 과정 (Direct Synthesis) 체감
1.  **연출 (2단계 - 코드 합성)**:
    *   `🧠 [LLM ⇄ RAG] 코드 생성 중...` 애니메이션 전개
    *   최종 Python 코드 출력 (`simva.set_signal(...)` 등) 확인.

### Step 4: 병목을 파괴하는 Pattern Cache 히트 시연
1.  **입력**: 위쪽 화살표(`↑`)를 눌러 동일한 문장 `"좌측 전조등을 켜라"` 재입력
2.  **연출 (Cache Hit!)**:
    *   `⚡ [Pattern Cache HIT!] -> LLM 연산 스킵 (0.001초 반환)` 메시지와 함께 기다림 없이 즉시 결과 반환.
